# 后续改进方向

本文记录希望做成的能力，以及和现状的差距。实现时按条目拆开做，不一次改完。

当前已有：登录、题库（搜索 / 难度 / 知识点筛选）、做题页、Python / C / C++20 评测、测试（只跑公开示例）、草稿、个人提交记录与成绩排行、管理员统计与全站提交、管理员网页增题。题库真源仍是 GitHub 的 `problems/`。

## 1. 提交数据、排行与后台

已实现：

- 管理员「管理」页：全站计数、各题提交/AC、提交表（可看源码）。
- 用户「成绩」页与题目页排行：同一题、同一语言、最好一次 `AC` 的 `time_ms`。
- 测试运行不写库，不进榜、不改已通过。

`time_ms` 仍是整次运行墙钟时间，不是从源码推断的 `O(n)`。

### 用户侧

- 「提交记录」：本人正式提交历史。
- 「成绩」：各题各语言最好 AC 与名次。
- 题目页：当前语言排行榜。

未 `AC` 的提交不进榜。

### 管理员后台

`/admin` 统计与全站提交；`/admin/problems` 增题。不在网页上改别人密码、不删账号。

## 2. 持续增加题库

### 现状

三道种子题：`two-sum`、`valid-parentheses`、`longest-common-prefix`。出题流程见 [problems.md](problems.md)。

### 做法

- 在能 `git push` 的电脑上新增 `problems/<slug>/`，推送后评测主机 `bash scripts/update-from-github.sh`。
- 每题至少：题面、签名、公开测例 2～3 条（`hidden: false`）、若干隐藏测例（`hidden: true`）、Python / C / C++ 的空 starter（与力扣一样，不要占位 `return`）。
- 签名与力扣一致，便于对照；C 按自由函数展开（指针 + 长度 / `returnSize`）。
- 网页「管理」只作应急。不要 Ubuntu 改盘与 GitHub 同时改同一题。

建议顺序：数组 / 哈希 / 栈 / 双指针 / 字符串的 easy，再补 medium。语言适配器（JS / Go / Rust / Zig）有余力再做，见 [adapters.md](adapters.md)，不阻塞加题。

## 3. 「测试」与「提交」分开

已实现。题目页两个按钮：

| 按钮 | 跑哪些测例 | 是否写入成绩 | 失败时展示 |
| --- | --- | --- | --- |
| 测试 | 仅 `hidden: false`（题面示例） | 否 | 每条的输入、期望、实际输出 |
| 提交 | 全部测例 | 是 | 与原来相同，隐藏测例只给序号 |
